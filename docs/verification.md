# Security and efficiency verification

The participant's original evaluation reported Code Quality, Testing, Accessibility, and Problem Statement Alignment at 100; Security at 95 and Efficiency at 85. No written rationale was provided. Those are reported baseline scores, not scores for this update. The changes below address demonstrable gaps while preserving the existing features and architecture. A later official evaluation is needed to determine any score change.

## Changes and evidence

| Concern                  | Change                                                                                                                              | Verification                                                                                                                                                                                                                                                          |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Repeated inference       | Up to eight successful results can be reused for five minutes in one memory-only workspace, using every input field as the key.     | Unit tests cover isolation, expiry, capacity, changed inputs, failures, aborts, and reset during a pending request. The desktop/mobile browser regression sends the same question three times and observes one HTTP request, then a fresh request after New document. |
| Excess simultaneous work | Three concurrent generations per warm instance; excess requests receive 429. Existing per-client/per-instance rate limits remain.   | Handler tests hold three requests open, reject a fourth, and verify capacity is available after failures.                                                                                                                                                             |
| Abandoned work           | Propagate the request signal to the SDK and reject aborted output.                                                                  | Pre-aborted requests never call the generator; in-flight cancellation reaches it and returns a sanitized response. Google may still process and bill already submitted work.                                                                                          |
| Oversized PDF extraction | Stop after the first page that pushes cumulative text above 40,000 characters.                                                      | A synthetic over-budget first page causes no later page extraction and destroys the worker; page-count and valid-text regressions also pass.                                                                                                                          |
| Downloaded Markdown      | Encode untrusted context, model strings, and source quotations at export.                                                           | Hostile image/link/HTML/code/heading syntax is escaped; the input analysis remains unchanged. Ordinary legal punctuation remains readable when rendered.                                                                                                              |
| Credential history       | Full-history Gitleaks scanning, including a Google AQ-prefix rule; CI pins action commits and verifies the scanner binary checksum. | An isolated fixture with a synthetic credential committed and then deleted is still detected, with redacted findings. The real repository history contains no detected secrets.                                                                                       |

In the repeated-question scenario, question HTTP requests fall from three to one: **66.7% fewer requests** for that exact workload. The browser test mocks inference to make the count deterministic; it is not a claim of 66.7% savings across all users or provider bills. New questions and changed documents still require inference. No runtime dependency was added.

The production entry JavaScript increased from 371,917 bytes at the baseline to approximately 372,390 bytes (109.86 KB gzip). PDF parsing remains in a separate lazy chunk. The small cache adds bounded memory use in exchange for fewer repeated requests; it never persists legal text or shares it across users.

## Reproducible checks

- `npm run verify`: lint with zero allowed warnings, strict types, 41 unit/API tests, coverage, client/API build, emitted-Node runtime smoke test, and formatting.
- Coverage scope: `server/**` and `src/domain/**`, excluding type declarations; 100% lines (145/145), statements (154/154), and functions (29/29); 94.28% branches (99/105). This does not claim UI coverage.
- `npm run test:e2e`: all 18 tests passed, covering desktop/mobile review, comparison, questions, downloads, PDF parsing, navigation, cancellation, request reuse, keyboard navigation, and axe checks.
- `npm audit --omit=dev --audit-level=moderate` and `npm audit --audit-level=high`: dependency advisories.
- `npm run preflight`: tracked size, single local branch, credential signatures, generated-file hygiene, and required documentation. Remote visibility and branches are checked separately before release.
- `npm run test:live`: opt-in real Gemini review, comparison, and questions against fictional public documents, with schema and exact-source validation. This can incur provider charges.

The original production Lighthouse mobile run scored Performance 98, Accessibility 100, Best Practices 100, and SEO 100 on 13 September 2026. Lighthouse measures page loading and browser behavior; it does not measure redundant model calls or total inference cost. A Vite plugin-timing diagnostic in the local update build reported 894 ms in plugin hooks out of 33 seconds, with overlapping CSS transforms; the build and emitted runtime checks succeeded. That diagnostic is not a production latency measurement.
